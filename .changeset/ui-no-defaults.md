No context of the package has a default, as `createContext(key)` in `brumate` now takes only a key. Reading one with no provider throws. The parts still render alone: each reads these contexts with `$getContext(Context, undefined)` and guards on the value, and a part outside an `I18nProvider` still uses `en-US`, with `$store($getContext(LocaleContext, store(DEFAULT_LOCALE)))`. Code that reads these contexts itself does the same. The contexts are `ButtonContext`, `LinkContext`, `ToggleButtonContext`, `ToggleGroupContext`, `ToolbarContext`, `HeadingContext`, `TextContext`, `LabelContext`, `SeparatorContext`, `GroupContext`, `LocaleContext`, `LayerContext`, `InputContext`, `TextAreaContext`, `FieldInputContext`, `FieldErrorContext`, `FormContext`, `CheckboxGroupContext`, `RadioGroupContext`, `ListBoxContext`, `ListBoxGivenContext`, `CollectionFocusContext`, `SectionContext`, `SelectValueContext`, `VirtualizerContext`, `MenuTriggerContext`, `MenuContext`, `SubmenuContext`, `DialogContext`, `TreeContext`, `TreeRowContext`, `TokenFieldContext`, `TokenContext`, `TableContext`, `TableRowContext`, `TableResizeContext`, `ColumnContext`, `NavigationTreeContext`, `NavigationLinkContext`, `DisclosurePanelContext`, `DisclosureGroupContext`, `OverlayTriggerContext`, `ModalOverlayContext`, `ColorSwatchContext`, `ColorPickerContext`, `DatePickerContext`, `CalendarContext`, `CalendarGridContext`, `DateStringsContext`, `DateFieldContext`, `DateRangeFieldContext`, `ColorThumbContext`, `ColorWheelContext`, `TransitionContext`, `TabsContext`, `TagGroupContext`, `SliderContext`, `TooltipTriggerContext`, `ToastRegionContext`, `ToastContext` and `SelectionIndicatorContext`.
