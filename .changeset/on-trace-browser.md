`start` of `brumate/loader` and `brumate/static-loader` takes `onTrace`, which gets a span for each event (`brumate.event`, with `brumate.load` for the code the handler waited for and `brumate.run` for the handler), each server function call (`brumate.fetch`) and each navigation (`brumate.navigation`). The spans of one event share a trace. A call and a navigation to the same origin send a `traceparent` header, so the spans of the server join the trace. Spans carry no arguments, results, query strings or form values. A call or a navigation joins the trace of a handler only when the handler makes it before its first `await`, since handlers overlap; a later call is the root of a trace of its own. A request to another origin sends no header, and a page with `onTrace` does not load the page of a link early, so each navigation sends it. A navigation has its route pattern, such as `/items/[id]`, once the page arrives, and no path when it fails. The Vite plugin leaves all of this out of a client build whose entry does not pass `onTrace`; the new `trace` option (`true`, `false` or `'auto'`) sets it when the entry is elsewhere.
