`$signal`, `$memo`, `$gate`, `$debounced`, `$throttled`, `$optimistic` and `$untrack` work at the top level of a `.brm.ts` module and of `<script module>`. They give one shared value per module, which components read like their own values and write only through functions that the module exports (a `<script module>` signal or optimistic value can also be written by the script of its own file). A signal compiles to `store()`, a memo to `derived()`, a gate to `gated()` and a debounced or throttled value to `timed()` of `brumate/store`, and an optimistic value to `optimisticStore()` of `brumate/client`, so a module that uses none of them adds nothing to the page. A debounced or throttled module value is pending while it waits, so `$isPending` and `$resolve` of a component work on it, and `$resolve` takes a name imported from a module. A write through an import is BRM117 with advice, a top-level form that cannot compile (`$effect`, `$client` and the forms that need a component) is BRM211, and `brumate check` reports a module signal that a plain `.ts` file imports as BRM208.
