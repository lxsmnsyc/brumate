# Log: promise-in-markup

- 2026-11-02: worktree at origin/feat/browser-async 2b1d12ca.
- Probe of the base: the server already awaits a promise in a text insert (`$$b.insert` gives a promise, the render awaits it), also inside an in-place `#loading` body, so the page waits there. `$$b.attribute` renders a promise as no attribute. The browser writes a promise as empty text and no attribute (`insertValue`, `attributeText`), in renders and updates.
- Server `#loading`: a body renders in place when nothing in it can wait (`mayWait`), else it always shows its `#else` and streams. The server cannot tell a settled promise from a pending one, and a speculative in-place render would either run the expression twice or need to merge a child context into the page. Chosen: `mayWait` also counts an insert or attribute whose value can be a promise, as it already counts a prop. Such bodies always stream, as bodies with a component do.
- Server attributes: `attribute` of server.ts waits for a thenable; `spread` waits for thenable values; a dynamic element waits for its spread. Codegen wraps attributes and spreads in `ready` on the server (not for primitives).
