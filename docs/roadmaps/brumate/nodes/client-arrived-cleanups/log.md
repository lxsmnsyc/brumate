- Difference worth knowing: on a partial route replace, the old route's markup is removed first and its cleanups run after, when the next state record is read (`dropScopes`). A full replace runs `leavePage` before the markup goes. A cleanup that checks `isConnected` sees different answers on the two paths.
- Coordinator's exact repro (goto /ui/switch, sidebar link to /ui/modal, first `article button[aria-expanded]`, `page.goBack()`, wait for pathname `/ui/switch`, assert no `[data-layer]`): reproduced the 1 leftover layer (`b7_0_1_4-0`, scope 17.0.1.4) with #355's overlay files and a fresh website build, and the log showed no cleanup after Back.
- Cause: a timing race in the check, not in the core. `goBack()` changes `location.pathname` at once (popstate), while the router fetches the previous page. A partial replace runs the old route's cleanups when the new page's state record is read (`dropScopes` from `routeRecord`, client-routes.ts). With a probe that waits 1.5 s after the pathname: `record drop=17`, `drop 17`, `remove 17.0.1.4` (2 cleanups), `remove -6` run, and `[data-layer]` is 0. Checked right after the pathname: 1.
- Same on the Back page when the layer count is read immediately in the earlier probes with a 500-800 ms wait: 0.
- Fix for the e2e step of #355 (not here, #355 is not on main): wait for the new page, such as `waitForFunction(() => !document.querySelector('[data-layer]'))` or the heading of /ui/switch, before the assert. No core change.
