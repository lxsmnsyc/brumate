# Log: template-context

- Proof on the base (fa137b5b): removed the `template-context` cause and its `diverge(...)` line from `test/differential/data.ts`, then `npx vitest run test/differential-3.test.ts -t tplContextListPage` (in packages/brumate). It fails: the browser render has `errors: ["Error: The context \"tpl-level-store\" has no provider above this component ..."]`, empty html. The server render shows 7.
- Cause as in the brief: `templateCall` built a `TemplateCall` with `lexical = true`, so `Children.from` was undefined, the scope of the template got no `t`, and `findProvider` walked `p` past the child.
- Fix: `TemplateCall` is always children of its owner (the `lexical` flag is gone). `createScope` then sets `t` on the template's scope to the scope that inserts it, as for children.
- That made `renderedTemplate` (inserts.ts) find two calls at one scope, because `scope.t === at` matched without the range test that `scope.l === at` had. `resume.test.ts` "updates each call of one template in its own scope" failed. The range test now applies to both.
- Probe `<TplProvider>{row('inside')}</TplProvider>` (`tplContextInFilePage.brm`): the browser render already matched the server on the base, so there was nothing to fix. The page stays as a guard in the differential test.
- Under load, "computes the memo of a template that a shallower component renders" (500 ms waitFor) and "leaves no markup when the block switches back" failed while two other workers ran; both pass alone three times, and on the base.
- Rework (2026-11-19): the first version landed as 1c96dc1f and was reverted (f7c5f578), because `pnpm --filter @brumate/ui exec vitest run test/datefield.test.ts` failed 2 of 10 ("steps a segment around its range ...": expected 'dd' to be '25'; "types digits into each segment ...": wrong focused element). The first review ran no ui unit tests.
- Split the two parts: with the `lexical` removal alone (inserts.ts as on the base), DateField passes 10 of 10. The range test in `renderedTemplate` breaks it.
- Cause: `datefields.brm` passes `#template custom(item) { <DateSegment ... /> }` to `DateInput`, which calls it in a `#for`. The template's scope only renders a component, so no node in the range names it: the range holds `b<DateSegment scope>:` and the segment's own `b-b`, never `t<template scope>:`. `inRange` looked only for the scope's own anchors, so the resumed scope (server state has both `t` and `l` set to the insert) was not found, the first update re-rendered the segment, and the test's `day` node and the focus were gone. The server render is right; the runtime lookup was wrong, so DateField needs no change.
- Fix: `inRange` counts an anchor of any scope whose `p`/`o` chain reaches the template's scope, and the kept nodes (`n`) of the scopes inside it (`children`, `owned`).
- Regression test: resume.test.ts "updates in place a template prop that only renders a component, which a child calls" (fixtures `tplPropCellPage.brm`, `TplPropCellList.brm`, `TplPropCell.brm`). It fails with the reverted version (the inputs are replaced) and passes with the fix.
- `TplPropCellList` joins the differential opt-outs (it needs the `cell` prop of its page). Root `pnpm test` and e2e website,ui pass.
