# Log: drop-unread-memos

- Measure first. A script (analyze + buildGraph from `packages/brumate/src`) ran on all 618 `.brm` files under packages/ui, website and examples. 351 `$memo` declarations; 0 with no read at all, 0 read only by `await`, 0 pruned by the new rule. The script found 2 of 6 in a probe page, so it counts. The change removes no code from real pages here; it is a rule for future ones.
- `await` read of a memo: in the browser a statement `await side;` compiles to a plain read, and `countLoads` does nothing without a boundary (`HAS_LOADING || HAS_ROOT_WAIT`). So `unreadMemo` is still the only reporter for a memo that only an `await` reads. Kept for that case.
- Rule: `findUnread` in graph.ts. A memo is unread when every read is inside the compute of another unread memo (fixpoint). Not candidates: `await $memo`, `$debounced`/`$throttled`, `$optimistic`, `$searchParam`, bound values, ref targets. A read in a function counts as a read, even if the function is never called.
- Plan: unread memo sites are not roots of `reach` and their nodes are removed from `live`, so the reads they hold give no slot to other memos and no `m` part is written (first probe showed `a` kept a slot and a client part only because unread `b` read it).
- Emitter (client mode, `emitStatements`): a declarator of an unread memo is skipped; a statement with other declarators keeps them. The patch can rewrite `const`, so the `let` rewrite before an `await` still slices from the statement offset when the statement is whole (first try broke `const { id } = $props()` in the differential test).
- Tests of #415/#417: the ones for a memo that nothing reads (also read in another unread memo, or `await` only inside one) now expect that the compute does not run (`failRuns` counter in the data files) and no error. The statement `await side;` and `awaitReadTry` still expect one report. New fixture awaitShownHost (alive memo reads it with `await`): one report.
- Differential: 5 pages now match (AwaitFieldKid, AwaitMemoKid, AwaitSumKid, PrimitiveAwaitUnreadKid, UnreadMemoKid). memoErrorAwaitServer still differs (an `await $memo` in a `#try`; the browser also reports to onError), so cause memo-reject stays with 1 page and its reason is reworded. AwaitShownKid (new, throws on purpose) is an opt-out like AwaitReadKid.
