# Outcome: brumate-check

## Built

- `brumate check [--json] [--no-types] [paths]` (`packages/brumate/src/check-command.ts`, wired in `cli.ts`). It compiles every `.brm` file with the project's live props, then runs `brumate-tsc` and reads its output. It exits with 1 on an error. Warnings print and do not change the exit code.
- JSON: one object per line, with `file` (relative, null for a project-wide problem), `range` (`start` and `end`, each `{line, column}`, 1-based, or null), `severity`, `message` (without code or place), `code`, `link` and `source` (`brumate` or `typescript`). A warning has a null code. A TypeScript record has a `TS` code and a null link, and its end is its start.
- Codes: each entry of `ERRORS` in `error-catalog.ts` has a literal `BRMnnn` code, BRM001 to BRM179 in catalog order, and a link `https://brumate.dev/docs/errors#brmnnn`. The header of the file states the rule: never renumber, never reuse, a new entry takes the next number. A test checks that codes are unique, increasing and well formed.
- Messages: `BrumateError` and `CompileError` write `message [BRM012] (File.brm:3:7)`, so the code shows in Vite's overlay, the language server and `brumate-tsc`. `findError` accepts the code. The message text is unchanged.
- Docs: `website/docs/errors.md` is one page with one anchor for each code, generated by `renderErrorsPage()`. A test fails when it differs (`UPDATE_SKILL=1 npx vitest run test/check-command.test.ts` writes it). The site had no page for compile errors, so this is the only new page. `typescript.md` documents the command, and the skill mentions it.
- Changeset: `.changeset/brumate-check.md` (minor).

## Deviations

- brumate-tsc has no API for its errors: it only has `run()`, which ends the process. `check` runs its bin and parses the lines. It needs `@brumate/tsc` installed and a `tsconfig.json` in the current directory, or it skips the type check with a note on stderr. `CheckOptions.tscBin` points to another script, for the test.
- Outside the owned paths: `error.ts` and `compile.ts` (the code in the message), `test/skill.test.ts` and `test/parser.test.ts` (their helpers strip the code before comparing), `skills/brumate/SKILL.md` and `references/errors.md` (generated, now with codes), `website/src/docs.ts` (sidebar), `website/docs/typescript.md`.

## Gotchas

- A new compile error needs an entry with the next free code. Take the number after the highest one in `error-catalog.ts` and regenerate with `UPDATE_SKILL=1 npx vitest run test/skill.test.ts test/check-command.test.ts`. Two PRs that add entries at the same time both pick the same number: the second one to land renumbers its own entry only.
- Tests that compare a whole message with a place need to strip ` [BRMnnn]`.
