# Log: element-values

- Linked node_modules, built brumate dist (the types import `brumate/signals`). Baseline `npx tsc --noEmit -p .` passes on main.
- Wrote the new cases in test/elements-types.ts first. With the old elements.d.ts, `tsc --noEmit -p .` exits 1 with 26 errors, at least one for each widened value (class array, class object, style object, select value, bound value and checked, bound textarea, server function in action and formaction, numeric strings for tabindex, maxlength, rows, colspan, li value, autocomplete boolean, `onKeyPress`, missing `EventHandler`). The 10 guard cases (rejections) pass on both.
- Runtime check of each widened type:
  - `class`: runtime/html.ts `classValue` (arrays join recursively, objects add the names with a true value, falsy items add nothing) and `attributeText` (`class` goes through it). `ClassValue` has string, false, null, undefined, arrays and objects. A number or `true` would render (`String(value)`), but the brief wants a number rejected, and `n && 'x'` is the only way to get one, so it stays out. A top-level `true` would render a bare attribute, so it is out too.
  - `style`: runtime/html.ts `styleValue` and `toKebabCase`. Entries with `null`, `undefined` or `false` are dropped, the rest print `String(item)`. Camel-case names become kebab case, `--` names stay. So `StyleObject` allows string, number, false, null, undefined, camel-case names of string properties of `CSSStyleDeclaration`, and `--*`. `cssText` and `cssFloat` are out (the kebab name is not a property), and `webkitX` is out (`webkit-x` lacks the leading dash).
  - `value` and `checked` bindings: analyze.ts allows `$bind` on `value` or `checked` of `input`, `select` and `textarea` (the `onElement` check near line 1685). runtime/client/handlers.ts lines 187 and 198 write `field.checked` for a checkbox or radio and `field.value` otherwise; runtime/html.ts `attributeText` and runtime/server.ts line 3783 read a binding for `value` and `checked`. So the type is `BindableMark<unknown> & WritableMark<string>` for `value` and `WritableMark<boolean>` for `checked`, as `ref` does. A signal of a number is rejected, because the field writes a string. `checked` stays on `input` only.
  - `select value`: codegen/markup.ts line 1059 treats `value` of a select like a field. Plain value is `string | number`, as on `input`.
  - `action` and `formaction`: codegen/markup.ts `formAction` takes an identifier of a server function (kind `server-function`, or a `'use server'` import) and calls `$$b.action`. Both are async (analyze.ts line 515). `ServerFunction` is `(...args: any[]) => Promise<unknown>`. The types cannot see which async function is a server function; the compiler decides. A string URL still renders through `attributeText`.
  - Number attributes: a static attribute is a string, and `attributeText` prints `String(value)` for either. `Attr<number>` became `Attr<Num>`, `Num = number | \`${number}\``, for every attribute that had it (tabindex, maxlength, minlength, size, cols, rows, colspan, rowspan, span, li value, ol start, meter and progress values).
  - `autocomplete`: runtime/html.ts `SWITCHES` has `autocomplete` as `['on', 'off']`, and `attributeText` maps a boolean to the word for any element. So `input`, `textarea`, `select` and `form` take a boolean.
  - Events: lib.dom has `keypress` (deprecated) and no `toggleend`, so `ToggleEnd` goes and `KeyPress` is added.
- `EventHandler<E, Ev = Event>` is exported; the internal `Handler<Ev, E>` is an alias of it.
- Checks: `tsc --noEmit -p .` passes, `tsc --noEmit -p tsconfig.elements.json` passes, oxlint exits 0, oxfmt --check passes. `npx vitest run` in packages/brumate: 972 passed, 5 expected fail.
