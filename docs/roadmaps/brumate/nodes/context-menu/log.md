# Log: context-menu

- Checked first: no `trigger` prop on MenuTrigger, no `shortcut` on DialogTrigger, position.ts only takes an element. Not fulfilled. Dependencies docs-collections, popover-sizing (adds `fitHeight`, `--anchor-*`) and split-ui-examples (sections, e2e modules) are in the base.
- Prior art (Terracotta ContextMenu and CommandBar, proposals.md #4): a boundary that opens on `contextmenu` and puts the panel at the cursor; a dialog with a shortcut on `window` that yields to a handler that wants it. Kept: the area is any element inside the trigger, the menu stays a real Menu, the shortcut yields to a handler that prevented it. Left out: separate CommandBar parts, as the proposal says.
- Design: `trigger="contextmenu"` renders a different wrapper (`display: contents`) with `onContextMenu=(stop(prevent(...)))`, so the prevent runs before the handler code loads and an inner area wins over an outer one. The area is the children other than the Popover (a Popover renders in a portal, so its events do not reach the wrapper).
- Placement: `followTrigger` takes `Element | Anchor`; `pointAnchor(x, y)` is a zero-size rect, `OverlayTriggerState.point` carries it to Popover. Default offset is 0 for a point, `bottom start`, so flip, clamp and RTL come from computePosition. A ResizeObserver is not set on a point.
- Keyboard: the browser sends `contextmenu` for the context menu key and Shift+F10 (Chrome, Firefox), with coordinates that differ by browser. The wrapper marks whether the last input was a key or a pointer; for a key the point is the bottom-left of the focused element and focus goes to the first item. For a pointer focus goes to the menu (same as a press), like MenuTrigger.
- Touch: iOS Safari sends no `contextmenu`, so a timer (LONG_PRESS of preview.ts, 500 ms, slop 10 px) opens it; the click after it is swallowed. Android sends `contextmenu`; whichever comes first opens it and the other finds it open.
- Browser menu: while open, a document `contextmenu` listener (capture) prevents the browser menu everywhere and closes the menu for a target outside its layer. The page is inert while the menu is open, so the target of a right click outside is not the area.
- `Menu` has no `aria-labelledby` in a context menu (MenuTriggerState.triggerId is optional now): there is no Button to name it. Docs say to pass `aria-label`.
- Shortcut: `matchesShortcut` in shortcut.ts follows `keyMatches` of the runtime (same modifiers, Shift does not count) but compares a single letter in either case. `prevent('Mod+K')` compares `event.key` as it is, and Cmd+K sends `k`, so the same string with `prevent` never matches. Not touched here.
- Shortcut rules: listener on `document`, bubble phase, so a handler on an element that prevented the key keeps it; ignored for `repeat` and composing; closed + text field focused -> ignored unless `shortcutInInput` (my reading of the proposal: "skips the shortcut while an input has focus unless the author says otherwise"); open -> toggles wherever focus is. Registered with `$client(..., 'load')`, which prints the usual compiler warning for 'load' ("runs before any interaction") like Popover and ModalOverlay do. 'idle' would avoid it, but the shortcut would wait for idle.
- Tests: `unmount` of brumate/testing does not run the cleanups of $client, so the test takes the keydown listeners off itself; otherwise a stale instance of DialogTrigger prevents the key for the next mount. The test also waits for a `ready` signal set by a `$client(..., 'load')`.
- Docs: menu.md (use case + keyboard row), autocomplete.md (palette recipe now uses `shortcut`; the old AutocompletePaletteDemo was replaced by CommandPaletteDemo and removed). dialog.md was not edited (not owned); the DialogTrigger props table shows `shortcut` and `shortcutInInput` from the doc comments.
- Review fixes: a right click outside moves the menu (close, then `openOnceFree` waits for the page to be usable and opens at the point when the area is under it; the page is inert while open, so the event target is not the area). A scroll outside the menu closes it. `Menu` warns once in development (`import.meta.env.DEV`) when it is in a context menu and has no `aria-label` or `aria-labelledby` (`MenuTriggerState.isContextMenu`). Docs: user-select, bullet moved, dialog.md pointer, same-shortcut note.
- Chrome check fix: the site search (website/src/components/Search.brm) skips a keydown that is already defaultPrevented; the demo uses Mod+J (the site search owns Mod+K); e2e step in the website overlays flow.
