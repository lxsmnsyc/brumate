# Questions for the maintainer: partial-route-responses

Everything else is decided in `brief.md` and the child briefs. The children assume the recommended answers until you decide.

## 1. Are partial responses cached?

The partial body depends on the client: the kept layout scope IDs and `x-brumate-base` are in it. Today `pageKey` (`runtime/server.ts:3965`) already includes the base, so the page cache stores one copy for each base value.

| Option                                                                                                                                     | Prior art                                                                                                                                                                                                                                                                                                                                                                 | Cost                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| A. Cache by `x-brumate-keep` and `x-brumate-base`, with `Vary` on both                                                                     | Next.js varies on its router headers ([cache.ts](https://github.com/vercel/next.js/blob/a86aeba10e7b32041ead6e252f807ad080166ef6/packages/next/src/client/components/segment-cache/cache.ts)); htmx advises `Vary: HX-Request` ([hx-target.md](https://github.com/bigskysoftware/htmx/blob/fa978b24e75fb03c137bf2cdae4fef0e711cf8a1/www/content/attributes/hx-target.md)) | many keys, low hit rate; CDNs that ignore `Vary` can serve a partial to a full request |
| B. Never store partial responses in the page cache or shared caches (`cache-control: private`); only the browser's prefetch map keeps them | Turbo frames are not cached ([frame_controller.js](https://github.com/hotwired/turbo/blob/e1936dfeef1878a582b27e13bada5f74b9b2e575/src/core/frames/frame_controller.js))                                                                                                                                                                                                  | the server renders each partial navigation; full pages stay cached                     |
| C. A separate URL for partial responses (`?_partial` or a `.data`-style path), cached like a page                                          | React Router `.data` requests ([single-fetch.tsx](https://github.com/remix-run/react-router/blob/c9a237a0bd095714fd0111c7e49e18768e1eb8ba/packages/react-router/lib/dom/ssr/single-fetch.tsx))                                                                                                                                                                            | safe with any CDN, but changes URLs seen in logs and needs the same IDs in the key     |

Recommendation: B for 0.9.0. The body holds the client's IDs, so a shared cache would almost never hit, and A risks a wrong answer from a CDN that drops `Vary`. Add C later if a measured hit rate justifies it.

## 2. What does prefetch fetch?

Today a hover fetches the full page and a click within 10 s reuses it when `x-brumate-base` matches.

| Option                                                                                                                                                             | Prior art                                                                                                                                                                                                                                                                 | Cost                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| A. Prefetch the partial response, with the current keep header. A click reuses it when `x-brumate-keep` and `x-brumate-base` still match, and loads again when not | Next.js prefetches with the router state tree ([app-router-headers.ts](https://github.com/vercel/next.js/blob/a86aeba10e7b32041ead6e252f807ad080166ef6/packages/next/src/client/components/app-router-headers.ts)); React Router prefetches only the route data of a link | smallest hover cost; a changed keep tree wastes the prefetch                  |
| B. Prefetch the full page as now; a click uses it through `planRoutes`                                                                                             | Turbo prefetches full pages and swaps them whole                                                                                                                                                                                                                          | bytes on every hover stay at the full page size; no coupling to the keep tree |
| C. Prefetch only on pointer down or touch start, partial                                                                                                           | htmx `hx-trigger="mousedown"` pattern                                                                                                                                                                                                                                     | least waste, least time saved                                                 |

Recommendation: A. It keeps the saving where hovers happen most, and the keep tree rarely changes within 10 s; a mismatch falls back to one normal partial request.

## Answers (the maintainer, 2026-11-18)

1. B: partial responses are never stored in the page cache or shared caches (`cache-control: private`).
2. A: hover prefetches the partial response with the current keep header; a click reuses it when keep and base still match, else it loads again.
