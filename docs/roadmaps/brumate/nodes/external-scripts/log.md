# Log: external-scripts

- 2026-11-19: nothing existed (`<script>` in markup was BRM010, `trigger` unknown). Codes BRM205, BRM206 and BRM210 are unused in the pinned file, but BRM210 was used once in history, so the node takes BRM212 to BRM216.
- Prior art read from the pinned briefs, not copied as code: Nuxt Scripts triggers, Next `<Script strategy>`, Astro `is:inline`. The loader reuses the `b-client` scan and trigger code (`when`, `after` in `boot.ts`), so `idle` and `visible` share one path with `$client`.
- Form on the wire: the brief says the script sits inside the template. A static `<script src>` inside a template is inert, but the attributes of a script that are expressions (`src=(url)`) cannot be written there by the clone code, since a render cannot reach into `template.content`. So the attributes of the script go on the `<template>` itself (the browser fetches nothing for `src` on a template), and only the code of an inline script goes inside it, in an inert `<script>`. A raw `<` in the code would become markup in the template otherwise.
- The parser keeps the node as an element with `tag: 'script'` and a `script` mark (`trigger`, `inline`, `head`). `trigger` and `inline` stay in `attributes` for the type check and are filtered in `emitElement`. The tag, `b-script` and the nonce are decided there, so the analysis and the clone code see one element.
- Nonce: the server writes `$$b.attribute('nonce', $$ctx.nonce)` on the template and on the plain head script. The browser render writes none. The loader reads the nonce of the loaded page from `document.scripts` (`.nonce`, which the browser keeps when it hides the attribute), as `navigate.ts` does.
- Probe finding 1: the core scans markup before it is in the page, so `load` could not check `isConnected` at once. `load` waits one microtask. Found by the e2e step for a block that opens.
- Probe finding 2, a bug on a common path: `updateHead` compared `outerHTML`, which holds the nonce, and each response has its own. Under a CSP with a nonce, no head script was ever kept, so a plain head script ran again on every navigation. `headHTML` leaves the nonce out (behind the `scripts` flag).
- Probe finding 3: a head script with `src` and `data-rerun` was refused under `require-trusted-types-for` (`runnable` set `src` as a string). `runnable` now passes `src` through the policy.
- Size trap: rolldown keeps an import that a branch of a flag uses, when the branch's test reads a property first. `trustedScriptURL` as an export stayed in a build without scripts. It is now a second argument of `trustedScript`, so the string `createScriptURL` is gone from such a build (test in `test/external-scripts/features.test.ts`).
- The feature flag `scripts` is on for `b-script` and for any `<script … src=` in compiled code, since a plain head script with `data-rerun` also needs the policy method and the nonce-free comparison.
- Not done: the highlighter (`highlight.ts`) reads `<script …>` attributes as quoted strings only, so an expression attribute on a script is not coloured. The brumate skill has no text for scripts yet.
- Added `examples/external-scripts` (a copy of the shape of `examples/browser-async`) for the e2e suite, since the suites run built apps. It changes `pnpm-lock.yaml`.
- Fix round 1 (review): the `scripts` flag now comes from `plan.scripts`, which `emitElement` sets, not from a regex over compiled code (a `raw('<script src>')` shell turned it on). `onScript` refuses a non-http(s) `src`. `interaction` shares one set of window listeners. The `visible` observer is not disconnected when a block closes: the loader has no hook for a destroyed block, and the callback checks `isConnected`. The website builds with `features: 'all'` (playground), so its bundle holds the loader code in both builds; the bundle diff against the base is the new code only.
